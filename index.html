检索通道说明与自建代理

B 站搜索接口对浏览器跨域请求有风控限制：带上 Origin 头会被直接拦截，因此纯网页直连通常拿不到数据（这是 B 站的策略，不是本工具的缺陷）。要拿到可自动分析的结果，需要一条“代理通道”。

另外，B 站的检索接口要求请求携带 buvid3 / buvid4 设备指纹，否则会返回 412；纯浏览器脚本无法伪造它，所以下面两条通道的代码都已经内置了「先取指纹、再带 Cookie 检索」的处理，直接复制即可用。

森空岛接入说明与隐私边界

      
    

    

      
为什么必须先有一条转发通道

      
森空岛相关接口（as.hypergryph.com、zonai.skland.com）只对白名单来源返回跨域许可，网页直连一定被拦截。因此本工具把请求交给一条转发通道，按顺序尝试：同源 /skland → 本机代理 http://127.0.0.1:8787/skland → 你在「代理设置」里填的前缀。B 站检索可以没有代理（降级），森空岛读取必须有代理。

      
它会读取哪些数据

      
只读你自己账号里那部分：干员是否拥有、精英化阶段（evolvePhase）、等级（level）、技能专精（skills[].specializeLevel 取最大值）、模组等级（equip[].level）。不读取手机号、密码、身份证等任何信息，也不修改你账号里的任何数据。

      
凭证怎么处理和保存

      
扫码流程里本工具只知道二维码里的 scanId，token 与 Cred 都由鹰角 / 森空岛接口返回。凭据只写入本机浏览器 localStorage 的 akgf.skland.v1，不上传任何第三方服务器。转发脚本是无状态的：只把请求体原样转发给白名单域名并回传响应，不写日志、不落盘、不保存凭据。退出登录按钮会同时清掉本机保存的凭据。

      
什么时候会失效

      
森空岛 Cred 的授权期约 7 天。到期后「读取并写入 BOX」会失败，重新扫码或再用凭证导入一次即可，不需要重装或换浏览器。

      
常见失败与排查

      
    
        
  1. 提示转发通道不可用：代理没启动或端口被占用。确认 python proxy.py 正在运行，且浏览器能打开 http://127.0.0.1:8787/。
    2. 
        
  2. 扫码后一直停在「等待扫码」：二维码只能由手机上的「森空岛」App 扫（是 hypergryph:// 专用码）；过期就点「刷新二维码」。
    3. 
        
  3. 接口返回非 0 的 code：多为凭据过期或该账号未绑定明日方舟角色，重新登录一次即可。
    4. 
        
  4. 干员数量对不上：森空岛只返回你拥有的干员；个别特殊形态（如升变阿米娅 char_1001_amiya2）不在公开干员表里，会被跳过，不影响其余干员。
    5.
